# IngeTrazo D5 LiveSync 累積更新紀錄

## 0.9.10-test.2 — 2026-11-13，六項修正測試版

以 e461605 的 0.9.10-test.1 為基礎，來源仍為官方 IngeTrazo v0.6.0／e61132a。使用者明確授權清單頂端至「群組編輯內上色」共六項；不包含其後的其他精進項目。

1. 排除即時 camera_home：只變更瀏覽視角不再因這個欄位使模型相同檢查失敗。明確儲存的視圖、圖層、陰影及其他場景設定仍保留原檢查。
2. D5 關閉監測：在 IngeTrazo 端每秒觀察 D5Render.exe 主程序的生命週期（不以啟動器安裝路徑推測執行位置），獨立於 SDK 工作程序。曾確認存在後，持續消失至少兩秒才停止，顯示 D5 已關閉；保留未確認 revision 及 dirty 狀態。只結束橋接自己啟動的 Blender，不結束 D5 或其他 Blender。停止請求後原有三秒寬限仍適用。重開 D5 後按開始可新建連線。
3. 略過檢查診斷：sync_decision／sync_skipped 記錄 skip_check，包含回報狀態／雜湊、內容版本、epoch、追蹤序號、場景欄位、群組追蹤欄位與貼圖檔案可讀性／變更。不能反推舊包五輪的確切欄位，等待新實測確認。
4. 空局部更新：完整命令與狀態檢查通過、沒有待更新根群組、接收端已有成功基準時，只銜接主程式追蹤狀態，不匯出、不建立新 revision、不改 latest.json、不呼叫 D5。不影響手動完整更新、接收端要求完整更新或安全退路。
5. 預覽延後：依原生工具 start_point／grab／dragging 等狀態及 Scale 的 _grip 延後提交，涵蓋滑鼠放開、仍待第二次點擊的操作；手動更新保留在佇列，提交或取消後再處理。未知的外掛預覽狀態仍保守，不宣稱全面辨識所有第三方工具。
6. 群組編輯內 PaintCommand：沿用已核對來源雜湊，允許編輯中的面上色；未分組模型依然獨立判斷，局部處理及重新共享受影響的根群組。測試涵蓋退出編輯後的 Undo／Redo、共用元件重新共享及 hold 保留，不改材質工作室、原生模型、UID、UV 或圖層合併實作。

本地驗證：37 項 Linux／真實 0.6.0 core 測試通過，含實際 Qt 控制面板（offscreen）、原生 IGZ 匯出及局部合併；D5 程序／SDK 情境以測試替身驗證控制流程。Windows API 本體、實際 SDK 關閉／重連及本版大模型秒數尚未實機驗證。

限制：D5 監測需要先觀察到 D5Render.exe 主程序；若程序列舉失敗或主程序名稱不同，監測不會武斷停止，診斷 d5_monitor 會顯示 armed／probe_available。同步來源匯出期間主事件迴圈可能暫停，關閉偵測會在迴圈恢復後處理。五輪疑似重送僅修正可重現的視角欄位路徑並補足證據，不宣稱所有原因均已查明。

## 0.9.10-test.1 — 2026-11-12，測試版，待 Windows／D5 驗收

以儲存庫實際 0.9.9 原始碼為基礎。開發基準最初為 bee6c44，後同步 develop 的 2cd4d7e 管理文件；兩者 LiveSync 程式完全相同。未發布正式版。

- 核對診斷 6／7，及官方 ingelibre/ingetrazo 的 v0.6.0（e61132a7f8a098ca77fb6b0e7cac488c1bd410cb）。
- 一般群組原生移動／旋轉：原生程式修改頂點、UV 投影及 axes，xform 可以維持 None。這些已追蹤命令可在 UID、路徑、階層及其他屬性檢查通過後，使用原生 IGZ 儲存器局部更新受影響最外層群組。有獨立 xform 的元件保留原有快速矩陣更新。
- 材質工作室 0.5.1：支援已核對 engine.py 的 PaintCommand。以正規化換行後的 SHA-256 核對來源、完整命令追蹤、明確目標群組及未分組網格修改序號鏈判定。允許該命令造成的子群組複製與布林 component 標記清除；其他屬性、識別或階層不符則退回完整同步。
- PaintCommand 即使沒有上色未分組面仍會增加 scene.mesh 修改序號；只有已核對命令且沒有未分組面目標、未分組網格識別相同、每筆修改序號完整銜接時才接受這項副作用。
- 材質參照檢查涵蓋背面材質，避免漏掉共用同名材質的未分組面；局部快照包含所需背面材質庫項目。
- 沒有變動時，只有本連線已成功確認的版本與目前內容版本、命令追蹤、網格追蹤、群組、全域設定和貼圖檔案狀態一致才略過。不建立新 revision、不改 latest.json、不呼叫匯出器或 D5。手動「完整更新一次」及接收端要求完整更新不略過。
- 新增 sync_requested／sync_skipped、觸發來源、排程世代、內容版本、實際屬性欄位及移動前後有界頂點樣本。樣本及修改序號只作診斷，並非完整幾何證明。
- 原生 History 吞下的失敗／拒絕命令亦會使局部證明失效。
- 未更動 D5 importer、物件識別生成、圖層 hold 合併規則、官方 SDK 或使用者模型。局部處理依舊使用原有接收端合併與完整同步退路。

本地結果：22 項自動化測試通過，使用實際 0.6.0 core、原生 IGZ 匯出及局部合併；Python 語法編譯、diff 空白檢查通過。沒有執行 Windows／D5 實機測試，沒有新的實機秒數。

限制：這次一般群組移動走局部快照，不宣稱已轉為純矩陣傳送或達成 7 秒。材質工作室來源不同、缺少可讀 engine.py、編輯群組內上色、未分組面或其共用材質受影響、追蹤中斷、範圍過大等仍完整同步。先完整同步成功一次後才能最佳化；本次不改變既有完整合併的 hold 基準要求。
