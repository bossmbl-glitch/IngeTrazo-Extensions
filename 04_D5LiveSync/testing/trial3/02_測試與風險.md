日期：2026-11-16。程式基於已合併 develop 的 test.2：遠端唯讀核對 develop=dc9011e134a12103f204639d9a344af6de302fab，本地基準 a5e39dd8b902811307e47587a40ca53c9187ab39 的程式樹相同。沒有執行本輪 Git 分支、提交、推送或 PR 變更。

## 問題證據

使用者前一包 test.1 診斷含 002_天花=hold、62 個 _scope_ 材質；恢復後同一橋接專案的最新診斷為空圖層政策、0 個 _scope_ 材質，且首次完整同步已送來源材質。最新包沒有包含排除／恢復的完整操作鏈，不能據此還原每一步，也不能證明 D5 端所有覆寫的儲存方式。

已用舊 compose 離線重現：hold A 時 B 使用 _scope_ 名稱，排除 A（最後 hold 消失）時 B 切回來源名稱。另核對到完整 importer 會刪除零使用者的隔離材質，checkpoint 也無法保證保存沒有 fake user 的材質；名稱紀錄本身不足以保留 Blender 上的 SDK 屬性。

## 風險與未驗證

- 尚未執行 test.3 Windows／Blender／D5 實機驗收，沒有新效能數字。不能把來源名稱穩定等同 D5 一定保留全部自訂覆寫。
- D5 備份與目前 bridge.blend 可能已不匹配；本版不會猜測或重新創造已丟失的 SDK UUID。先測首輪重連的副本。
- 排除仍會移除輸出的物件；D5 是否保留移除物件的獨立覆寫不受橋接器完全控制。未操作圖層的識別保留與被刪除物件的覆寫恢復，需要分開驗收。
- 為保留識別，本版保留曾用的材質與別名；Blender 檔、快照資源及備份可能增加，不會自動刪除歷史材質。
- 歧義／未知舊資料會停止更新，避免改名硬送。這類錯誤不能靠退回完整同步安全解決，需保留診斷再查。
- 橋接自動備份不包含 D5。回復外掛版本也不會自動回復橋接檔，完整 projects 備份仍必要。
