# 0.9.10-test.6 圖層保留顯示修正

來源：遠端 develop dc9011e（本輪唯讀核對未變），本地 HEAD a5e39dd，加上尚未提交的 test.3～test.5 累積修改。Git 操作未執行，沒有正式發布。

## 原因與修正

舊流程以全域圖層定義及凍結子層別名隔離可見性。相同圖層可同時用於保留樹及正常樹，單一 Blender collection 的隱藏旗標無法代表兩份不同狀態；原生 IGZ 又可能省略預設可見圖層。這些結構問題可在本地資料重現，但本輪沒有新的 Windows 診斷，不能斷言已定位使用者畫面的唯一觸發路徑。

新增 visibility.py，完整組合時計算每個群組的有效可見性（祖先、群組 hidden、圖層 visible），保留樹沿用上次成功快照的逐群組紀錄。預設省略的圖層解讀為可見；舊快照首次升級依其確認內容計算。散線／散面依 Layer 0 記錄。凍結前已隱藏的內容維持隱藏，不強制開啟。

完整／局部 importer 建立或重用物件後，在送 SDK 前先驗證所有群組識別，再將自有共享圖層 collection 設為可見，按逐物件旗標控制顯示。正常樹使用來源當前狀態，保留樹使用基準；不調整其他文件。純位置更新沿用既有可見性紀錄，不增添重建路徑。缺失／重複／損壞紀錄會停止，不以不確定內容硬送。

不再因顯示衝突新增 _scope_hold_ 圖層別名；既有基準的名稱保留。此修正不寫材質、不改物件鍵、UV、集合歸屬或 SDK UUID；材質名稱／別名帳本與 fake-user 保留仍沿用 test.3。保留模式禁止同時做舊材質整理。首次可見性升級前、圖層政策切換前均保存並保留上一份確認橋接配對。

## 限制

- 尚未執行 Windows／真實 Blender／D5 材質繼承驗收，沒有新效能秒數。本地欄位及材質對應不變，不能視為實際 D5 覆寫絕對不會重置的證明。
- 需要可用且與 D5 相符的成功橋接配對；以前遺失的 SDK UUID 仍無法重建。若舊基準本來已錯誤隱藏，不能猜測成可見。
- 控制範圍仍依最外層群組；保留不是排除。恢復正常後來源若仍隱藏，D5 會跟隨隱藏。
- 保留內容可能在其他圖層完整同步時被重新處理／傳送；不代表零傳輸。原本安全完整同步退路保留。
- 移機與備份仍有 test.4／test.5 的限制；D5 在伺服器，不打包資產，不支援跨機同步鎖。
