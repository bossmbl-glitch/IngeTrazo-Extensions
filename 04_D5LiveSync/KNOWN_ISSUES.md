## 0.9.10-test.1 待驗收限制（2026-11-12）

- 一般群組 baked move 使用局部 IGZ，尚未提供純矩陣快速路徑，未量測新 Windows／D5 秒數。
- PaintCommand 僅支援可讀且雜湊符合已核對版本的來源；未知版本、未分組材質影響、編輯群組內上色等仍完整同步。
- 舊診斷缺少精確 UI 觸發來源；本版已補紀錄，不能反推過去是哪個按鈕／訊號。
- 實際 D5 物件識別、既有材質關聯、UV、hold、大模型與重連行為待使用者 Windows 實機驗收。
- 詳見 testing/01_驗收清單.txt 與 02_診斷核對與測試結果.md。

## 0.9.10-test.4（2026-11-16）

- 配對還原點不包含 D5／IGZ，需相同時期副本。不能自動找回安裝前已遺失的 SDK UUID。
- 還原只支援同一專案與原路徑；舊 optimization-backups 保留原處，不自動猜測匯入。
- 保留點、損壞證據及 rescue 現況保全不自動清除，可能占用較多磁碟。
- 檔案與 Qt 流程本地測試通過；真實 Windows Blender 檔存取／SDK／停電持久性仍需實機驗證，不能保證硬碟實體故障後可恢復。

## 0.9.10-test.5（2026-11-16）

- 已新增明確移機流程，test.4 直接複製／還原的原路徑限制仍適用；跨路徑請使用「匯入移機包」。
- 95 項本地測試通過；未驗證 Windows Blender／官方 SDK／D5 伺服器專案的跨機材質繼承、效能與實體斷電情境。
- D5 專案及資產不打包、不搬動、不檢查版本。原始 IGZ 需另外帶，識別不符會拒絕。本機鎖不能阻止另一台同時同步。
- 匯入後失敗可能留下已驗證的新增備份，原橋接配對依還原交易回滾；未知／損壞／舊 optimization-backups／rescue 證據保留原機，不打包。
- 大型 ZIP 壓縮與匯入驗證會暫時占用介面，需足夠 staging／備份空間；上限 20,000 檔與 100 GiB 解壓總量。
